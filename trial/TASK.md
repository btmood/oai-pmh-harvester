# OAI-PMH 采集任务的恢复与发布

我们用这个项目定期采集机构元数据，并将生成的 XML 交给下游索引程序。一次采集可能持续很久；进程中断时，下游仍应读到上一批完整结果，重启后应继续这批采集。

请在现有项目中实现下面的能力，补充测试和使用说明。保持现有 CLI 不带新选项时的行为兼容。

## 命令约定

在 `harvest --method list` 上增加：

- `--state-dir PATH`：启用本地持久化采集状态。
- `--checkpoint-every N`：每处理 N 条记录至少持久化一次进度，正整数，默认 1000。
- `--resume`：从指定目录恢复同一批采集。

示例：

```text
oai -h http://127.0.0.1:8765/oai -o output.xml harvest --method list --state-dir .harvest-state --checkpoint-every 3
oai -h http://127.0.0.1:8765/oai -o output.xml harvest --method list --state-dir .harvest-state --checkpoint-every 3 --resume
```

本次新增能力只要求本地输出文件和 `list` 方法。与 `get` 方法或 S3 输出组合时，应明确报参数错误。原有日期、集合、metadata format 和 `--exclude-deleted` 过滤继续生效。

## 必须实现的行为

1. **输出完整性。** 最终文件保留原来的 `<records>` XML 格式及记录内容，使用 UTF-8。这批输入保持稳定；重试和恢复可能重放同一标识符的同一条记录。按标识符去重，顺序按首次看到该标识符的顺序确定。删除标记遵循 `--exclude-deleted` 的选择。
2. **原子发布。** 整批采集成功前保持已有输出文件逐字节不变；失败时退出码非零，保留可恢复状态。成功后一次性发布完整 XML。首次运行失败时，最终输出路径应保持不存在。没有记录的合法结果成功发布空的 `<records>` 文档。
3. **进程级恢复。** 已持久化的数据与进度在进程重新启动后仍可使用；恢复时校验二者一致。允许重新获取最后一次检查点之后的数据。对仍有效的分页 token，继续其对应页面；如果服务端明确返回 `badResumptionToken`，允许重放该批原始查询，通过持久化状态去重。其他协议错误应保留状态并明确失败。能够处理发布已经完成、状态完成标记尚未写入就中断的情况。
4. **批次身份与占用。** 状态绑定源地址、最终输出的绝对路径、metadata format、日期范围、集合和删除过滤。恢复参数不匹配时，在写输出或变更原状态之前明确拒绝。未带 `--resume` 时拒绝复用已有批次状态。对已经成功完成的批次，重复恢复应幂等。两个进程同时使用同一状态目录时，第二个明确失败；进程异常退出后可以恢复这份状态。
5. **规模与兼容。** 记录量增加时采用流式处理或磁盘状态，避免将整批记录或全部标识符常驻内存。保留原有命令和测试的语义；新增测试覆盖正常运行、失败恢复、过期 token、参数不匹配和重复恢复。

实现方案和状态格式由你决定。请运行已有测试及新增测试，说明完成的功能、验证结果和使用方式。

现有 `trial/` 文件是提供给你的输入材料，请保留其内容；可以在其他位置增加测试和文档。
